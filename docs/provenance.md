# Provenance

Append only. A reversal is a new entry.

## 2026-11-09: initial Windows 2000 theme (0.1.0)

- **What:** `index.client.ts` registers one light theme, `windows-2000`, with eight colors from the Windows 2000 "Windows Standard" scheme. Manifest, overview, README, and two screenshots added.
- **Who asked:** Marcel W. Wysocki asked for a Windows 2000 theme for the Paseo themes category, based on his win2k.css, and for it to be published.
- **Color source:** `--sys-*` values in [maci0/zine `src/gui/win2k.css` L106-L148](https://github.com/maci0/zine/blob/a17c2d1e9f056876f2bef186dfc03aca25a74cd6/src/gui/win2k.css#L106-L148), annotated there as the `HKCU\Control Panel\Colors` defaults. [maci0/clanker `themes/win2k.json`](https://github.com/maci0/clanker/blob/main/themes/win2k.json) carries the same values.
- **Token mapping:** chosen from how Paseo expands a light plugin theme in [getpaseo/paseo `packages/app/src/plugins/themes/index.ts`](https://github.com/getpaseo/paseo/blob/1fff127f45b11c1c9c573fbbd12791673004c912/packages/app/src/plugins/themes/index.ts) (`buildLightPluginTheme`): `background` also colors popovers, the terminal, and text on the accent; `control` colors inputs and the sidebar; `border` colors the user message bubble and sidebar hover (`packages/app/src/components/message.tsx:316`); `ring` colors sidebar selection, placeholders, and extra-muted text.
- **Decisions:**
  - ButtonFace as `background` with Window white for `control` and `raised`, over the inverse (white background, ButtonFace sidebar and cards). Both were registered and rendered side by side; the chosen one reads as a Windows 2000 dialog with white list wells, the other as a gray-tinted modern light theme.
  - `mutedForeground` is ButtonDkShadow `#404040`, not GrayText `#808080`: on `#d4d0c8` the contrast is 6.7:1 against 2.6:1 (WCAG relative luminance).
  - `ring` is GrayText `#808080`: it must work both as text on ButtonFace and as a background under black text, and `#808080` is the Windows 2000 color that does both.
- **Verification:** `bun run typecheck` passes. Installed as a directory plugin with `@getpaseo/cli@0.15.3`; `plugin ls` reports `running` on the local daemon and on an isolated daemon with its own home. In the bundled 0.15.3 web UI, computed styles on the Appearance screen show exactly `rgb(212, 208, 200)`, `rgb(255, 255, 255)`, `rgb(128, 128, 128)`, `rgb(64, 64, 64)`, and `rgb(0, 0, 0)`. Screenshots taken from the isolated daemon with a sample project.

## 2026-11-09: Windows 2000 window chrome (0.2.0)

- **What:** `client/chrome.ts` adds a stylesheet on web and desktop: `#3a6ea5` desktop behind the sidebar and main window, raised 2px window frames, active and inactive caption gradients (`#0a246a` to `#a6caf0`, `#808080` to `#c0c0c0`) on the workspace, settings, new-workspace and dialog panes, beveled caption, push and toolbar buttons, Win2k tabs, sunken composer, prompt and text fields, raised menus with navy hover, 16px scrollbars, Win2k cursors, square corners, Tahoma first in the UI font stack. `client/web.ts` injects it and marks bordered `<button>`s and dialog panels. The 0.1.0 palette is unchanged. Listing images replaced; the diff screenshot dropped.
- **Who asked:** Marcel W. Wysocki: "not win2k enough yet. needs the blue gradient etc" and "the blue win2k background".
- **Sources:** edge model, scrollbars, cursors and menu colors from [maci0/clanker `themes/win2k.css`](https://github.com/maci0/clanker/blob/main/themes/win2k.css); desktop and caption colors from the same `--sys-*` set as 0.1.0.
- **Mechanism, from the Paseo 0.15.3 web UI:** Unistyles writes theme colors as `--colors-*` variables on `:root`, with one shared `:root.pluginLight` class for every plugin light theme, so the stylesheet is scoped with `@container style(--colors-surface0: #d4d0c8) and style(--colors-surface2: #ffffff) and style(--colors-accent: #0a246a)`. Inside it the derived variables are overridden: `--colors-accent-foreground` white (fixes the 0.1.0 `#d4d0c8`-on-navy text), `--colors-surface-sidebar-hover` `#d4d0c8` and `--colors-surface-sidebar-selected` `#0a246a` (fixes 0.1.0 hover and selection sharing `#808080`), `--colors-surface3` `#d4d0c8` (secondary buttons), `--colors-primary` navy. Selectors use Paseo's `data-testid` names (`wide-shell`, `composer-dock-header`, `workspace-deck-entry-*`, `workspace-tab-*`, `message-input-root`, `user-message`, `sidebar-footer`, `settings-sidebar`, `settings-detail-pane`) and ARIA roles. Dialogs mount in their own `<body>` child, outside `#root`, so rules are scoped to `body`.
- **Why the DOM observer:** CSS cannot select on computed styles. Paseo's push buttons share only a build-hashed Unistyles class, so `client/web.ts` marks `<button>`s with a non-zero computed border; dialog panels are the first opaque `rgb()` fill under `role="dialog"`. `role="dialog"` is set by an attribute update after the nodes mount, so the observer also watches `role` changes, not only added nodes.
- **Verification:** `bun run typecheck` passes. Reloaded on an isolated demo daemon with its own home and checked in the bundled 0.15.3 web UI under Playwright Chromium at 1440x900 and 420x820: computed `--w2k-active` is `1` and the shell is `rgb(58, 110, 165)` under this theme, and under Light the flag is empty, the shell `rgb(255, 255, 255)`, the header has no gradient and corners are 8px again, all without a reload. Focusing a sidebar button turns the workspace caption `rgb(128, 128, 128)` and the sidebar caption `rgb(10, 36, 106)`; focusing the composer turns the workspace caption back to navy. Hovering the composer attach button gives the inset `#fff`/`#808080` bevel. The command center and add-project dialogs get a framed panel and a "Paseo" caption. Screenshots show only the sample project.
- **Not verified:** native iOS and Android (the code returns before touching the DOM there), browsers other than Chromium, and Tahoma rendering (not installed on the test machine).
